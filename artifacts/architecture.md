# Architecture: Local Task List

## Design

Use a small two-part local application:

- **FastAPI backend:** owns the API contract and an in-memory task collection. It has no database or external integrations.
- **React frontend:** renders the task list, calls the local API for mutations, and persists the canonical task list in browser `localStorage`.

On startup, the frontend reads its saved list from `localStorage`, displays it, then seeds the backend's in-memory collection with a full-list replacement request. This keeps browser storage authoritative across page reloads and backend restarts while ensuring subsequent API updates operate on the same task IDs. Successful API responses update the UI and `localStorage`; API errors are surfaced without silently treating a failed operation as successful.

## Data model

`Task`:

- `id`: stable string identifier generated by the backend when creating a task.
- `text`: trimmed, non-empty task description.
- `completed`: boolean, initially false.

## HTTP interface

Serve JSON under `/api` on the local development origin. Configure narrowly scoped local CORS only if the development setup uses separate frontend and backend ports.

| Method | Path | Behavior |
| --- | --- | --- |
| `GET` | `/api/tasks` | Return the current in-memory list. |
| `PUT` | `/api/tasks` | Replace the in-memory list with the frontend's saved list during initialization. Validate incoming task records. |
| `POST` | `/api/tasks` | Create a task from a non-empty text value; return the created task. |
| `PATCH` | `/api/tasks/{task_id}` | Update the task's completion state; return the updated task. |
| `DELETE` | `/api/tasks/{task_id}` | Delete the task; return a no-content success response. |

Invalid text or malformed list records receive a 422 response. Unknown task IDs receive a 404 response. Keep IDs stable when replacing the collection so persisted browser records remain actionable.

## Frontend components and flow

- `App` owns task state, initial restoration/seeding, and API error display.
- `TaskForm` submits trimmed text and clears the field only after successful creation.
- `TaskList` renders an empty state or task rows.
- `TaskItem` exposes an accessible completion control and delete button.
- A small API client centralizes requests to the local `/api/tasks` routes.
- Persist the initial restored list and each successful mutation to `localStorage`; do not overwrite saved data on API failure.

## Local development

Run the FastAPI and React development servers locally. Configure the frontend to use the local API origin (or a local dev-server proxy). Document environment setup and start/test commands in the repository README. No account, credential, hosted service, or external database is needed.

## Test strategy

- **Backend:** test list, create, validation, completion toggle, deletion, missing IDs, and list replacement using FastAPI's test client.
- **Frontend:** test task rendering, add, toggle, delete, startup restoration/seeding, and persistence across reload-equivalent initialization with mocked local API calls and `localStorage`.
- Run the repository's targeted test commands and any available build/type checks; report unavailable coverage clearly rather than claiming it passed.
